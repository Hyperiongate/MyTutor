# CLAUDE.md — standing instructions for MyTutor (Mr. Cadabra)

Claude reads this file at the start of every session in this folder. Follow it every time.

## Who you are working with

Jim Dillingham owns this app (Hyperion Shift LLC). He is **not a coder**. He reads diffs but does
not edit code by hand, so never hand him a snippet to paste or a command he must type unless
there is no other way — and if there isn't, give him the exact text and say where it goes.

## Jim's rules (non-negotiable)

1. **Do no harm to existing functionality.** Never strip or simplify working code to get a
   quick result.
2. **Proper fixes, not duct tape.** The app is in development; it does not need to be up
   right away.
3. **Read the actual file before changing it.** Never guess at a file's contents.
4. **Complete edits, never truncated files.** Edit the real files in this folder in place.
5. **Check your work.** Run the dry run / battery (below), fix every error, and repeat until
   it is clean *before* telling Jim you are done.
6. **Dated change notes at the top** of every file you change (newest first, today's date).
7. **Every code file ends with the line:**
   `I did no harm and this file is not truncated.`
8. In any company or marketing copy, write "Hundreds", never "300+".

## Git and deployment — Jim does this part, not you

- **Never run `git commit`, `git push`, or anything that rewrites history** (`reset --hard`,
  `rebase`, `checkout --` over his changes, force-push). Leave changes uncommitted.
- Jim reviews with `git diff` (or the diff view) and pushes to GitHub himself. Render rebuilds
  from GitHub automatically.
- **API keys live only in Render's environment settings.** Never write a key into any file,
  never create a committed `.env`.
- For any backend change, **bump `APP_BUILD` in `main.py`** and tell Jim the new stamp. After he
  pushes, he confirms it at `https://mrcadabra.com/health` (the `build` value must match).

## Verifying a change

- The battery is `python ruletests.py` (it is large; let it finish). Report the pass / fail /
  skip counts. Never call work done with failures outstanding.
- `RULES.md` is generated by `python ruletests.py --rules` — never edit it by hand.
- If Python or the packages in `requirements.txt` are not installed on this computer, say so
  plainly and ask Jim before installing anything. Do not skip the check silently.
- Never kill the battery with `pkill -f "ruletests.py"` (it kills the shell too). Kill by PID.
